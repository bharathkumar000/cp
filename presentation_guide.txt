1. PROJECT OVERVIEW & VISION
----------------------------
* Concept: "Academic Nexus" uniting campus life, peer study, and AI intelligence.
* Goal: Replace fragmented student resources (drives, WhatsApp groups, portals)
  with a unified premium dashboard and mobile app.
* Achievement: Won 2nd Place at VVCE's State Level Hackathon "Parivarthan" 
  for architectural stability and premium UI/UX design.

2. CORE SYSTEMS ARCHITECTURE
-----------------------------
* Multi-Tier Architecture:
  [Client Layer] Next.js Web App / Flutter Mobile APK
       │
  [Server Layer] Next.js App Router API Routes / Node.js Companion (Port 5001)
       │
  [Data Layer] Supabase PostgreSQL Database (Real-time WebSockets)
       │
  [AI Engine Layer] Local Ollama / Groq LPU API / Gemini Flash API
* WebSocket Replication: Uses Supabase Real-time Channels (WebSockets) to 
  instantly push database changes to client UIs without polling.

3. WEB FRONTEND STACK - TECHNOLOGIES & JUSTIFICATIONS
------------------------------------------------------
* Next.js 16 (React 19 / ReactDOM 19):
  - Why we used it: Provides folder-based App Router, native server action handlers, 
    built-in optimization (images, fonts), and superior hybrid page rendering 
    (SSR for content-heavy notes/PYQs to boost SEO, and CSR for real-time portals).
* @supabase/supabase-js & @supabase/ssr:
  - Why we used it: Enables seamless integration with Supabase database, authentication 
    sessions sync, and cookie-based server hydration for server-side layouts.
* bhimupijs:
  - Why we used it: Generates standard BHIM-compatible Unified Payments Interface 
    (UPI) dynamic deep-linking URLs and strings for instant peer-to-peer 
    canteen/library transaction requests.
* face-api.js:
  - Why we used it: Implements browser-based AI face detection and feature 
    extraction (using pre-trained convolutional neural networks on TensorFlow.js)
    for instant biometric attendance validation.
* lucide-react:
  - Why we used it: Dynamic vector SVG iconography library. Chosen because they 
    render perfectly at any screen resolution and support CSS currentColor hover transitions.
* pdf-lib:
  - Why we used it: Runs raw JavaScript binary manipulations on PDF documents to 
    embed institutional seals, compile certificates, and generate structured 
    question papers directly in the client browser.
* razorpay:
  - Why we used it: Safe connection with the Razorpay Payment Gateway API for 
    handling card, net banking, and wall-wallet recharge payments.
* recharts:
  - Why we used it: Implements lightweight SVG-based data visualization charts 
    (bar charts, radar graphs) that scale responsively with clean rendering.
* sharp:
  - Why we used it: Performs ultra-fast, asynchronous image conversions and 
    scaling on the server side before uploading profiles to Supabase storage buckets.
* zod:
  - Why we used it: First-class runtime schema declaration and static validation 
    for incoming forms and API request payloads, preventing SQL injection and type crashes.

4. MOBILE CLIENT STACK - TECHNOLOGIES & JUSTIFICATIONS
-------------------------------------------------------
* Flutter SDK (Dart Language):
  - Why we used it: Single codebase compiling to native ARM machine binaries for 
    Android and iOS. Bypasses intermediate JavaScript rendering bridges for 
    fluid, lag-free 60fps animations.
* google_fonts:
  - Why we used it: Dynamically downloads and applies premium typography 
    (such as Space Grotesk and Inter) without inflating the initial asset payload.
* fl_chart:
  - Why we used it: Premium canvas-based mobile chart painter, used to render 
    responsive academic analytics and telemetry graphs.
* crypto:
  - Why we used it: Delivers standard hashing algorithms (like SHA-256) to 
    securely sign local user data packages.
* flutter_secure_storage:
  - Why we used it: Wraps OS-level secure storage modules (Android Keystore and 
    iOS Keychain Services) with AES-256 encryption to protect session tokens.
* provider:
  - Why we used it: Implements a clean dependency injection and state propagation 
    pattern, automatically rebuilding dependent widgets when datasets update.
* supabase_flutter:
  - Why we used it: Out-of-the-box Dart wrapper for PostgreSQL real-time listeners 
    and JWT authentication flows.
* http:
  - Why we used it: Standard REST protocol caller for direct HTTPS connections 
    to cloud models (like Groq) and backend routers.
* image_picker:
  - Why we used it: Accesses native Android cameras/galleries via native Intents,
    allowing students to scan handwritten homework/doubts.

5. AI & ROUTING LAYER - SPECIFICATIONS
---------------------------------------
* Multi-Tier System: Local Ollama (Primary) -> Groq API (Secondary) -> Gemini Flash (Tertiary).
* Groq Model: llama-3.1-8b-instant.
* Chat Guardrails: Incoming prompts are pre-validated by keyword searches. 
  Non-academic requests are blocked immediately by a regex filter.
* Math Parsing in Mobile: Custom Regex parser extracts inline/block math equations 
  and displays them cleanly using specific typography.

6. CHALLENGES FACED & IMPLEMENTED SOLUTIONS
--------------------------------------------
* CHALLENGE 1: Mobile APK loopback issues.
  - Problem: Emulators connect to localhost via 10.0.2.2. APKs on actual phones 
    crash when local dev servers are offline.
  - Solution: Direct HTTPS fallback to Groq API. When local requests time out 
    (fail-fast 8s), the app calls Groq APIs directly over HTTPS.
* CHALLENGE 2: Suspended free-tier Supabase project crashing client logins.
  - Problem: Paused free-tier Supabase endpoints crash client contexts with 
    network error: "Failed to fetch".
  - Solution: Developed a Polymorphic Mock Client (client.ts/server.ts). 
    Detects offline states, returning a mock interceptor that prevents crashes.
* CHALLENGE 3: Formatting and rendering complex LaTeX equations in Flutter.
  - Problem: Flutter Text widgets render formulas as unreadable plain text.
  - Solution: Created a Regex math tokenizer in prepcare_screen.dart. Extracts 
    $$...$$ and $...$, rendering them with stylized SpaceGrotesk fonts.

7. EXPECTED PRESENTATION QUESTIONS & VIVA CHEAT SHEET
------------------------------------------------------
Q1: Why Next.js 16 / React 19 instead of plain React?
A1: Next.js provides Server-Side Rendering (SSR), routing optimization, and API 
    handlers out of the box, reducing client JS bundle sizes and loading times.

Q2: How does Supabase ensure student privacy?
A2: By enforcing Row-Level Security (RLS) policies. Direct PostgreSQL calls 
    are authorized only if the user session matches the requested resource.

Q3: Why use both Flutter (Mobile) and Next.js (Web)?
A3: Flutter compiles directly to native ARM machine instructions for fast 60fps 
    mobile apps. Next.js offers high-speed web dashboards and SEO benefits.

Q4: What happens if the college internet is offline?
A4: The mobile app automatically shifts to standalone mode, invoking direct 
    cloud API endpoints (Groq/Gemini) over mobile data channels.

Q5: Why select Groq API as the primary fallback?
A5: Groq's LPU architecture generates tokens extremely fast, keeping chatbot 
    conversation flows smooth and lag-free.
